# Spec review — add-e2e-stage

Verdict: NOT-READY

Repeated run, using the Specs round answer Q38. No main specs exist for `e2e/*`: all three capabilities are new. There is no `sources/ui/`, so the UI mode checks do not apply. This run checks only the parts that changed: in e2e/stage, the gate requirement, "Test results stay valid until the code they tested changes", the decision requirement, the skipped requirement and the fingerprint wording; in e2e/tests, the retries scenario.

Previous findings: S13 is resolved by Q38 and the new requirement with its two scenarios. S15 and S16 are resolved. Part of S14, S17 and S18 remains (see below). S19 and S20 are new and come from the new validity rule.

| S19 | major | e2e/stage › "Test results stay valid…" vs "Project changes after the stage are caught" | The two requirements contradict each other after the stage is complete. Under the new rule, any change to application code outside the E2E folder makes every earlier result invalid. The stage is then incomplete, and the gate (stage/spec.md:41) blocks the archive. The other requirement lets the developer's decision "no new run is needed" unblock the archive. "Minor change asks the developer" (a typo in a code comment) and "Developer decides no new run is needed" cannot both pass: the comment edit is a change to application code, so every result is invalid and the archive stays blocked whatever the developer decides. | stage/spec.md:41, :74, :105, :112-115, :122-125; clarifications.md Q24, Q38 | Follow-up question: "After the E2E stage is complete, the AI makes a small edit to application code (for example a typo in a comment), and the developer says no new run is needed. Does that decision keep the earlier results valid, so the archive is allowed? Or does any application-code change always need a new run of every test?" Then make one rule govern both requirements. |
| S20 | major | e2e/stage › "Test results stay valid…" | The rule covers two cases: application code outside the E2E folder, and "one E2E test's own file". When one of these changes, nobody can tell which results become invalid. Q38 does not settle this. | stage/spec.md:74; clarifications.md Q28, Q38 | Follow-up question: "If the AI changes a file in the E2E test folder that is not a test of its own (a shared helper, a data fixture, the Playwright config), which test results have to be rerun: every test, or only the tests that use that file?" | S21 | minor | e2e/stage › fingerprint wording vs validity rule | The stage record keeps a fingerprint "at the latest run" (one value). The validity rule needs more than that. A single whole-project fingerprint taken at the latest run cannot do this. | stage/spec.md:74, :81-84, :105 | Say that every recorded run keeps its own fingerprint, with application code and each E2E test file fingerprinted separately.
