| S22 | major | ui-sources/screenshots › "Deleted screenshots are caught" vs "Screenshots switch the UI mode on" | The mode is on only while `sources/ui/` holds at least one screenshot, and without screenshots the change "SHALL behave exactly as before: no inventory and no UI check is required". If the developer deletes the last (or only) screenshot after the inventory is written, the mode switches off. No UI check runs, so the deleted screenshot is not caught. The inventory, with its `in scope` elements and their coverage, is then silently ignored. Q24 says a deleted screenshot blocks. Q1 says no pictures means everything works as before. Neither the specs nor the answers say which one wins, so a developer and QA cannot tell the expected result. | screenshots/spec.md:10, :86-92; clarifications.md Q1, Q24 | Follow-up question for the Specs round: "Если из `sources/ui/` удалили все скриншоты, а `ui-inventory.md` уже написан, что должен делать кит? A. Режим UI остаётся включённым, пока есть опись: следующий шаг и архив блокируются, пока ИИ не уберёт удалённые скриншоты из описи (пустая опись — режим выключается). B. Режим выключается: опись игнорируется, как будто скриншотов никогда не было. C. Not yet defined." Then add the matching scenario, for example "Deleting the only screenshot does not switch the checks off". |
