### Summary confirmation — Main round

- Метарепозиторий — корень с OpenSpec и китом и клоны приложений в своих каталогах, каждый со своим git и игнорируемый корнем; все спеки и изменения ведутся в корне, агент запускается из корня [D1] [desc].
- Делаем на линии 0.4 (она остаётся бетой) с учётом всех её частей: тест-кейсы, этап E2E, UI-источники, автономный apply и отчёт о реализации; «ничего не ломается для обычных проектов» сравниваем с 0.4 [Q7].
- За рамками: перенос собственного OpenSpec клона в корень, клоны как git submodules или отслеживаемые корнем, запуск агента из каталога клона; а также всё, что исключает документ требований (клонирование, ветки, защита main, контракт API, git worktrees) [Q2] [D1].
- Список клонов (имя и путь) хранится в файле проекта в каталоге OpenSpec корня, без зависимости от mise; doctor предлагает добавить найденные вложенные git-репозитории, которых нет в списке; клон из списка, которого нет на диске, doctor и проверки называют отсутствующим, а не «нет теста» [Q3] [D1].
- Кит ищет тесты с маркерами внутри клонов по правилам самого клона (незакоммиченные учитываются, игнорируемые клоном не сканируются), во всех местах: проверка трассировки, данные для test-reviewer, archive gate; путь теста показывает клон [D1].
- В плане проверки у строки сценария колонка «Репозиторий»: одно имя или несколько, тест нужен в каждом названном, уровень один; колонка обязательна, пока у проекта объявлены клоны [Q4] [Q5].
- Корень — такой же репозиторий для привязки сценариев и групп задач, его тесты засчитываются [Q12].
